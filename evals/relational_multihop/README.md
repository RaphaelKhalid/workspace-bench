# Relational multihop

In-house family (no external source). A two-hop possessive cloze — one professional hop, one
kinship hop ("Avery's landlord is Sam. Sam's sibling is Riley. In other words, Riley is
Avery's ___"). Do the readouts state the composed relation (`landlord's sibling`) **as one
phrase, in the right order**? Instrument `PROMPT_VERSION = "rel-v3+relgate-v4"` (plan 0043 rel-v2 prompts with the rel-v3
18-option list, #209 round 6; rel-v1 judged the two hops in two separate calls, so a pass could
be assembled from two phrases).

**Headline caveats.** (1) The prompt states both hops, so the prompt-only floor is saturated
(rel-v1: 0.94 native, 0.96 summary; `SATURATED` in `baselines/prompt_only.py`): read the lens
on the anti-text-inversion subset, or as lens − prompt-only. (2) **This family measures prose
readouts; a token list carries no order, so token methods score ~0 here by design** (a ranked
top-k list never states "X's Y"; rank is not order).

- **Bank:** `items.json`, 100 items (50 scenes × an a/b pair with the hops swapped), generated by
  the source repo's `gen_relational_multihop.py` (ported to `src/wsbench/adapt/generate.py`).
  Unchanged by rel-v2 (`bank_sha` of the file is the same; the ATI fingerprint moves only
  because the full read plan changed). Fields used: `id`, `scene`, `stimulus`, `hop1` (outer),
  `hop2` (inner).
- **Read sites** (`wsbench plan`; Camila 2026-10-30: "every position starting after the second
  sentence (including the full stop)"): `reads=full` (default) = every token of
  `". In other words, P3 is P1's"` — the full stop that ends sentence two through the possessive
  blank (`{"kind": "suffix_text", "text": ...}`; 9-12 Qwen3.6-27B tokens: 9 for 52 items, 10 for
  36, 11 for 6, 12 for 6; 966 positions × 11 layers = 10,626 cells per arm). `reads=lite` = the
  blank alone (`final_token`, today's read; a subset of the full span). Layers: `readplan.GRID`
  (L20..60 step 4) or any `layers=` subset (`all`, `each`, a csv).
- **Cells:** `reads.load` does the layer subset, the sidecar, the lite selection and the full
  span check (`min_full_positions = 8`, contiguous). The family then checks, per (item,
  layer): the last read position is the possessive blank (a row's `token` must be a suffix of
  `'s`; Gemma reads `"s"`), and under `reads=full` a run of 2+ positions starts on a token
  ending in `.`. Either failure raises with the id. A `prompt_only:` reader is waived.
- **Units and calls:** native = ONE call per (item, layer) on the bundle of every read position
  at that layer (`[L<layer> pos <p>]` headers, no token text); summary (the default) = ONE call
  per item on its digest of every read position × every judged layer. Key `<unit>:R`; a gold
  pick whose quote fails gate 1 is asked once more with `RETRY` appended, key `<unit>:R2`.
- **Pass rule.** unit pass = pick **G** (`hop1's hop2`) AND **gate 1** (the quote verifies with
  `digest.quote_ok` on the lines AND on `digest.statement_lines`, i.e. inside ONE top-level
  bullet of one sample; at most 15 words / 40 CJK characters) AND **gate 2** (the lexicon order
  gate below). Item pass = any judged layer (native) or the one summary unit.
- **Metric:** `pass_rate` = passing items / items in scope; bootstrap CI over items. Chance is
  stated one way: 1/18 per unit (the 18 content options; cannot-tell excluded, the
  lucky-guessing convention), native any-of-layers floor `1-(17/18)^n_layers`; both are upper
  bounds (a guessed pick also needs a verified, ordered quote). Lucky guessing (Opus shown only
  the list, rel-v3): blind 0.062, described 0.064, under the 1/18 + 0.05 bar — the list does not
  give the gold away (§Option list). In the macro (`not_in_macro = ""`).
- **Judge:** `claude-opus-5-5` (the repo default). Blind: no passage, no gold, no tool name.

## Gate 2: the order gate (`gate.py`)

Runs on `gate.fold` text (`digest.fold_quote` after blanks are replaced), never calls an API.
**Blanks** (audit F12, 2026-10-31; round 3: `rel-v2+relgate-v3`; round 4: `PROMPT_VERSION = "rel-v2+relgate-v4"`, the registered instrument; calls kept `CALL_VERSION = "rel-v2"`, so none was re-asked; round 6: `rel-v3+relgate-v4`, every call re-asked on the new list):
`fold_quote` strips `_` as markdown, so the fill-in frame `landlord's _______ cousin` used to
fold to `landlord's cousin` and count as stating the chain (rel-s01-a all-layer, rel-s45-a L52,
rel-s13-b L56 passed on it). A free-standing underscore run and a bracketed placeholder
(`(blank)`, `[___]`) now become a non-relation token that breaks every link. relgate-v3 (round
3): a run of 2+ underscores is a blank even when it touches a word (`barber's ____child`,
`cousin's________ coach`, `plumber's _______mother`: relgate-v2 missed these and passed rel-s38-a
and rel-s15-b all-layer, rel-s26-a and rel-s25-a lite, rel-s07-a L52 and rel-s14-b L60 on them;
all six now fail, nothing else moves); only a word span wrapped in the SAME 1-3 underscores on
both sides (`__cousin__`, `___child___`) is emphasis, and a lone `_` counts only when it touches
no letter or digit (`a_b` stays a word). A chain
followed by a possessive and a blank (`cousin's boss's ___. Here's why`) is embedded. A statement is scanned into relation
*mentions*, leftmost-longest over every alias in `prompts.REL_LEXICON` (EN incl. gendered forms
and plurals, ZH) plus `OTHER_RELATION_WORDS` (caretaker, teacher, partner, …): so "stepson" is a
stepchild, "表兄弟" a cousin, "牙科医生" a dentist; English aliases are bounded by
`(?<![\w-])…(?![\w-])`, so "grandson" or "sister-in-law" never read as child / sibling. Two
consecutive mentions are *linked* when the text between them is one possessive (`X's Y`,
`X的Y`, an optional short gloss: `房东 (landlord's) brother-in-law`) or `Y of (det|Name's){0,2} X`.

A gold pick passes gate 2 iff some statement (bullet) holding the quote states the chain
`hop1 → hop2` inside the quote, and the chain is **not embedded** (no mention links into it or
out of it, no trailing possessive: "aunt's landlord's sibling" and "landlord's sibling's ___" do
not state `landlord's sibling`), and that statement states none of the rival chains (every
other listed chain, incl. the reversed order, and every `NEAR` form of the gold; a
statement holding two listed chains singles out none, `extras.n_two_chains_in_one_statement`),
and no rival chain is stated in as many of the unit's statements as the gold (the prompt's "most
bullets/lines; a tie is cannot tell" rule, enforced mechanically: `extras.n_rival_prominent`;
in summary mode the count runs over every loaded cell's statements, since the digest keeps one
sample line per entry and marks its support, so a `[many]` gold beside a `[one]` rival is not a
tie). A
bare apostrophe links after an s-final word ("boss' sister-in-law"). A quote holding `" | "`
never passes (tokens of one list carry no order). Offline on the bank: the stimulus never passes either order (0/100),
`gold` and `gold_alt` pass 100/100, `flipped` passes 0/100.

## Option list

Nineteen lines (rel-v3, #209 round 6, 2026-11-01), built by `judge.build_options` (no API;
pinned by `tests/golden/relational_multihop_options_v3.json`, written by
`scripts/make_relational_options.py`): 18 content options seeded-shuffled
(`seeded_shuffle(content, f"{REL_SEED}:v3:{id}")`, `REL_SEED = 20260813`), then
`cannot tell from the readout` LAST (`mc.options_with_cannot`).

- Two decoy relations are drawn exactly as in rel-v2 (`Random(seed_int(f"{REL_SEED}:v2:draw:{id}"))`):
  `d1` from hop1's domain, `d2` from hop2's (kinship / professional). A third decoy `d3` is
  drawn (`Random(seed_int(f"{REL_SEED}:v3:draw:{id}"))`) from the domain of a seeded coin's
  side, hop1's or hop2's, and joins that side: one side has three words, the other two. The
  options are every chain `a's b` and `b's a` with `a` in the hop1-side set and `b` in the
  hop2-side set (12: the gold, the reversed order, 10 other chains), each of the five words
  alone (`ONE_RELATION`), and one near-form option (`NEAR_FORM`: a step-, in-law, grand-, god-
  or ex- form of a chain). The singles and the near form are the judge's error categories,
  never gold.
- **Why this shape.** Within a side the list is symmetric (swapping hop1 with its side's
  decoys, or hop2 with its side's, maps the list to itself), so nothing marks which words are
  the hops or which order is the gold, and the coin puts the gold's outer word in the two-word
  set or the three-word set equally often (52/48 on the bank), so even a guesser who reads the
  set sizes is at 1/12. The spec's first design (gold, reversed, both hops alone, near misses
  built on the hops, 2 other chains) let Opus shown ONLY the list pick the gold 89% of the time
  (lucky-guessing blind, 2026-10-30); a hop-symmetric 10-option version still 49% (the hops
  were the recurring words). rel-v2 (13 options: 8 chains of {hop1, d1} x {hop2, d2}, 4
  singles, 1 near form; retired, still rebuilt by `build_options(..., version="v2")` for its
  golden pin) measured blind **0.138** ±0.011 against the 1/13 + 0.05 = 0.127 bar: a guesser
  who only learns "pick a chain" is already at 1/8. rel-v3: blind **0.062** ±0.013, described
  **0.064**, uniform 0.066 against 1/18 + 0.05 = 0.106 (Opus 5.5, 5 draws,
  `rel-v3+relgate-v4`): both pass.
- `NEAR` (prompts.py) holds each relation's near misses — always a *different* relation, never a
  synonym. They are not listed one by one (that marked the hops); the order gate treats each
  gold near form (`hop1's n`, `n's hop2`) as a rival chain:
  - `sibling`: step-sibling, sibling-in-law, cousin
  - `child`: stepchild, grandchild, godchild, niece/nephew
  - `parent`: stepparent, grandparent, parent-in-law
  - `spouse`: ex-spouse, fiancé(e), sibling-in-law
  - `cousin`: niece/nephew, aunt/uncle, sibling
  - `landlord`: tenant, realtor, roommate
  - `dentist`: dental hygienist, pharmacist
  - `boss`: coworker, employee
  - `coach`: teammate, referee
  - `tutor`: student, classmate
  - `plumber`: electrician, carpenter
  - `neighbor`: roommate, friend
  - `barber`: tailor, manicurist
  - `lawyer`: accountant, client
  - `mechanic`: electrician, driver
  - `doctor`: nurse, pharmacist, patient
  - `therapist`: client, nurse
- Example (`rel-s00-a`, gold `landlord's sibling`):

```text
  4. sibling's mechanic

  8. landlord's child
  9. mechanic's spouse
```

## Judge prompts

Templates are rendered with `str.replace` per placeholder. Every judge prompt appends the shared
token-list rule `mc.token_note(SPEC.flat_types, multi_select=SPEC.multi_select)` (this family:
`flat_types=()`, `multi_select=False`, so the rendered note equals `SUMMARY_NOTE_TOKENS` below);
the family's "most lines / tie → cannot tell" rule only adds to it.

### `JUDGE_SYSTEM`

```text
You judge readouts of a language model's internal activations, decoded while it read a passage you cannot see. Readouts are noisy, may be in any language, and often reason aloud.
Question: which ONE listed relation does the readout state, as a single phrase, for the relationship being asked about? Rules:
- A composed option "X's Y" counts only if ONE phrase inside ONE readout line states exactly that chain in that order: "X's Y", "the Y of (someone's) X", or the same in another language (e.g. "X的Y"). Synonyms, gendered forms (brother/sister for sibling, son/daughter for child, husband/wife for spouse) and translations of a relation word count.
- Never assemble a chain from two phrases or two lines: "John's child's caretaker" plus "his grandson's landlord" is NOT "child's landlord". In a free-text line, bullets are separated by "⁞"; each bullet is its own statement, so the chain must lie inside one bullet and the quote never crosses a "⁞".
- The chain must be exactly these two relations: a step-, god-, grand-, great- or -in-law form is a different relation ("stepson" is not "child", "sister-in-law" is not "sibling"), and a phrase that is part of a longer chain ("aunt's landlord's sibling", "landlord's sibling's ___") does not state the two-relation chain.
- The reversed order is a different option.
- A single bullet or line that states two or more of the listed chains states none of them.
- If several listed options are each stated (each in its own bullet or line), pick the one stated in the most bullets/lines; if two are stated about equally often, or the readout states none, choose "cannot tell from the readout". Choose a "(one relation only)" option when the readout names that relation but never in a chain with another listed relation.
- Do not use world knowledge or plausibility to fill gaps.
Give the SHORTEST verbatim quote (copied exactly from inside one line) that states your chosen option; leave it empty for "cannot tell".
```

Copy one phrase from a single readout line that states only the relation you chose; if no line does, answer "cannot tell".

## Token readouts

No interpretation step (plan 0032 §2.3; the rel-v1 per-cell `interp-v1` call is gone): natively a
token cell is judged as its raw ranked list (`family.render_bag`), under summary mode through the
same digest as every other method. A token quote can verify (one token, or tokens of one list
joined by `" | "`), but it never passes gate 2, so token methods score ~0 by construction.

## Summary mode

The default (plan 0024). Every loaded cell of an item — every read position × every judged
layer — goes into ONE digest call (`digest.collapse(..., task_note=SPEC.task_note,
expect_all=cells)`, which raises if a loaded cell is dropped); `layers=[44]` feeds only L44's
span. The composed-relation MC is asked once on the digest (key `<id>|L-1:R`), the readout block
being `BUNDLE_SUMMARY`. The quote is verified against the digest's evidence lines (whole readout
samples) and their bullets, exactly as natively; a chain is never assembled across lines, layers
or bullets. Item states: no readouts → rowless fail; unsummarized or failed call → fail counted in
`n_unjudged_cells`; empty → fail counted in `n_empty_cells` (both count items).
`prompt_version = digest.prompt_version("rel-v3+relgate-v4", args, "relational_multihop")` (defaults:
`rel-v3+relgate-v4+digest-v5-task-extractive+sj-v10`), `+reads-lite` under `reads=lite`.

### `BUNDLE_SUMMARY`

`{note}` = the digest note, `{summary}` = the item's digest.

```text
{note}

{summary}
```

### `SUMMARY_NOTE`

```text
The readout below is a digest of the readouts across every read layer and position: for each read layer, a note-taker who did not see the passage picked the most prominent readout samples, then samples carrying content seen in only one or a few samples, and the layers' picks are merged, the most-stated first. Each line is marked with how many readout samples state its content ([N samples], or [N samples, M layers] when it was seen at M read layers): counted per claim, so a sample that only lists the word among others of its kind, or only restates the question, is not counted; compare these counts when weighing lines against each other. Each line is one real readout sample (a free-text generation, or one ranked list of top tokens). Treat each line as a separate sample: pieces on different lines never combine. Any quote must be copied from inside one line, without the bracketed marker.
```

### `SUMMARY_NOTE_ABSTRACTIVE`

`{note}` under `summ_render=abstractive` (ablation).

```text
The readout below is a digest of the readouts across every read layer and position, written layer by layer by a note-taker who did not see the passage, most prominent first, then content seen in only one or a few samples. The statements are not evidence: judge what the evidence spans show, treat each line as a separate sample (pieces on different lines never combine), and copy any quote from inside one evidence span.
```

## Failure accounting

`n_expected_cells` counts (item, layer) units (summary mode too); `n_missing_cells` is 0;
`n_empty_cells` counts units whose every read position is empty (natively; items in summary
mode) — never judged; `n_unjudged_cells` counts non-empty units with no verdict (API failure,
summary failure); an in-scope item with no judged unit is a fail. Verdicts are cached
append-only in `<out>/cells.jsonl`, keyed by the call key and a fingerprint of
`(prompt_version, judge model, reasoning, system, user)`; a rerun retries only failures.
